# Prospective confirmation on new non-arithmetic tasks

This study addresses the earlier pilot's reuse of extraction and aggregation
tasks. It adds **30 researcher-authored tasks using preserved real public
records**, across **six source projects**, with ten tasks per relationship
family. These are adaptations of real records, not collected production prompts
or original user requests. No source values are generated by a model.

The frozen protocol is in [protocol.json](protocol.json). Actual completion and
outcomes belong in [REPORT.md](REPORT.md) and `evidence/summary.json`; preparing a
dataset or passing offline controls is not a completed model experiment.

## Sources and questions

| Family | Source project | Tasks | Actual records used | What is checked |
|---|---|---:|---|---|
| Date ordering | Node.js Release | 5 | v16, v18, v20, v22, v24 lifecycle schedules | Choose two supplied dates, preserve source values and order them strictly |
| Date ordering | endoflife.date | 5 | Python 3.9–3.13 lifecycle records | Choose a valid interval from that cycle's actual milestone dates |
| Identifier matching | SPDX license-list-data | 5 | MIT, Apache-2.0, BSD-2-Clause, MPL-2.0, ISC | Match the exact requested identifier and preserve the entire corresponding record |
| Identifier matching | IANA media types | 5 | application/json, xml, pdf, zip, octet-stream | Resolve the subtype identifier without mixing names and registration links |
| List membership | Prometheus Operator | 5 | First five actual ClusterRole rule blocks | Select an explicitly allowed verb for that exact API-group/resource block |
| List membership | Homebrew | 5 | jq, git, curl, wget, ripgrep formula records | Select a platform tag with an existing stable bottle |

[sources.json](sources.json) records original URLs, retrieval timestamps and
SHA-256 hashes. GitHub sources are pinned to commits. IANA, Homebrew and
endoflife.date API snapshots are byte-preserved, time-stamped snapshots, not
commit-pinned data. They may include forecast release/end-of-life dates and must
not be treated as permanently current facts.

The IANA registration link is a documented deterministic transformation of its
`Template` field, using the registry's public base URL. It is not a literal
URL-valued CSV field. Source arrays are permuted deterministically so the right
identifier is not always the first candidate. No candidate values are fabricated.
No external links are fetched or tools executed during generation.

## Untouched has a limited meaning

The selection audit uses baseline
`ab363ae4931542db402beaa383da09b08d6dc927` and all tracked files under
`research/`, `benchmarks/` and `tests/`. [exposure.json](exposure.json) preserves
the audited file hashes and exact prompt/context overlap results. The six source
identifiers were absent from that baseline's inspected text. SchemaStore was
rejected during selection because the earlier research had already examined it.

These facts support **new to the inspected local studies**, not absent from
model pretraining, unknown external experiments or unseen work. The earlier
private pilot reused main-study tasks; its private archive is not republished or
claimed as independently scanned here. The study has three authored instruction
templates and six source clusters, rather than 30 independent workflow designs.

## Freeze and independent validity

`freeze.json` seals the cases, protocol, source manifest, raw snapshots, decoded
YAML and exposure audit **before any study inference**. The runner rejects a
changed freeze and a resume with changed runtime code or settings. A new protocol
requires a new version and fresh tasks; do not overwrite a started pack.

The semantic scoring oracle uses direct date comparisons, exact record equality
and membership. It does not call HESchema's projection or relationship evaluator.
It runs only after generation and bounded repair. Its judgments are never used
as repair feedback. Structural checks use the same JSON Schema standard/library;
the semantic implementation is independent, not a second independent schema
engine. The Blaze cross-check remains available in the repository's validator
tests.

There are **190 offline controls**: all **100 valid alternatives** enumerated by
these tasks, 60 structurally valid corruptions and 30 malformed-JSON controls.
The corrupted values are synthetic test probes, explicitly excluded from live
inputs. Both the independent oracle and runtime accept every enumerated valid
alternative and reject every corruption. Ordinary shape schemas accept the 60
semantic corruptions. This demonstrates the chosen checks' behavior on controls,
not a live failure rate or proof that ordinary schema authoring cannot express
any of the constraints. A source-derived `enum` can express many finite choices.

The user waived human review for the research. Review here consists of source
reconstruction, independent deterministic checks and test controls; it is not an
independent human review or a second-model judgment.

## Controlled comparison

Thirty tasks × three models × three repeats × two prompt arms gives **540
scheduled initial generations**, with at most one runtime-triggered repair per
slot. Models are `openai/gpt-oss-120b`, `openai/gpt-oss-20b` and
`qwen/qwen3.8-27b` through Groq.

- **FULL:** projected output schema, approved binding values, relationships and
  trusted facts.
- **COMPACT:** original schema, binding locations, relationships and the same
  trusted facts; the identical full contract is checked after generation.

Both arms use prompt-only generation, temperature zero, a 2,048-token output
budget, the same source context and one repair with category-specific feedback
limited to 1,000 characters. There are no application calculations, provider
schema-enforcement requests or extra oracle retries. Models may use different
provider-supported reasoning defaults; GPT OSS requests low reasoning effort.
Groq does not receive a seed through this adapter. The recorded seed controls
schedule/arm permutation; temperature zero is not a reproducibility guarantee.

The three repeats measure consistency, not additional independent tasks. Request
order is randomized and arm order counterbalanced. Credentials are assigned to
workers before execution, never changed in reaction to a quota error. Each worker
is paced. Each worker permits one 120-second quota wait and retry on the same
credential per invocation. Another quota error on that worker stops the
invocation, including a new error after an earlier recovery. Other provider
failures also stop it, with partial evidence retained. Keys do not imply
independent quota pools.

An unfinished repair resumes from the saved initial generation. It does not
regenerate a successful initial call or double-count its usage. Output caching
is disabled. Provider failures and missing responses remain visible; comparison
tables use complete matched pairs and state their denominators. Usage includes
all returned attempts, including prior checkpoints. Provider errors may lack
usage, so recorded tokens cannot establish actual billing.

The runner uses previously authorized credentials described as free-tier; it
cannot inspect account billing or independently enforce the account's billing
configuration. It requests no paid provider or paid-tier change. Reported token
savings are observed usage, not verified financial savings.

## Reproduce

From the repository root:

```sh
python -m pip install -e '.[dev]'
python scripts/build_confirmation_pack.py
python -m heschema.confirmation_run
python -m pytest -q tests/test_confirmation.py tests/test_confirmation_analysis.py

# Set authorized credentials in the environment, never in committed files.
# GROQ_API_KEYS accepts a comma-separated list; GROQ_API_KEY accepts one.
python -m heschema.confirmation_run --execute --out results/confirmation-v1
python scripts/analyze_confirmation.py results/confirmation-v1
```

After provider quotas recover, `scripts/resume_confirmation.py` can copy a
checkpoint to a fresh directory and resume with a **longer** worker interval.
It preserves the original configuration, summary and journal hash in a session
history, refuses changed runtime code and never overwrites the prior directory.
Keep the same authorized credential pool and retain the failed slot's credential
when setting worker order. Published session histories identify relative worker
assignments without publishing credentials. A pacing change does not change
tasks or model settings, but makes cross-session latency comparisons unsuitable
for causal claims.

The default command is offline and makes no provider calls. All raw traces and
reasoning stay under ignored `results/`. The exporter accepts only this frozen
new public-source pack; it publishes exact final content, token counts, judgments,
timings and hashes, while omitting reasoning and HTTP headers. It refuses mock
or unconfirmed model responses. Earlier private experiment archives are excluded.

`scripts/build_confirmation_pack.py --capture` downloads a **new** snapshot;
`scripts/freeze_confirmation.py` seals an unstarted pack once. Do not invoke either
capture or freeze to modify a study after inference has started. Rebuilding from
the preserved sources without `--capture` is deterministic and does not change
the sealed case bytes.

## Analysis and interpretation

Report first/final correctness, all returned tokens, observed wrong acceptance
and correct rejection, repair recovery, and results by model and family. Include
all failures, rather than selecting favorable examples. The offline schema-only
acceptance counterfactual rechecks the same outputs; **there is no ordinary-schema
generation arm** and no basis for claiming HESchema improves that arm's generation.

Average repeated/model outcomes within each task before computing task-level
paired differences. Bootstrap entire source projects, preserving related tasks;
six clusters still provide weak uncertainty estimates. A zero-width empirical
interval on a ceiling-effect sample is not proof of equivalence or zero errors.

Provider client response time, local checking, dispatch pacing, quota waits,
coordinator time and session wall time have separate scopes. A replayed initial
response is not charged again as new provider latency. Concurrent throughput and
client response time are not model inference time. No causal speed claim follows
from this run's timing.

This study broadens the tested declared relationships. It cannot prove coverage
of arbitrary workflows, all calendar/time-zone semantics, case normalization,
wildcard authorization, multi-record joins or unknown constraints. It also does
not establish that a custom JSON Schema vocabulary is necessary.
