# Rebuilding the frozen H60 cases

The builder uses the checked-in document
`docs/reports/HESchema_60_Real_Record_Tasks.md`, not a nonexistent repository-root
copy. Both the source bytes and generated case bytes are pinned:

| Artifact | SHA-256 |
|---|---|
| Source Markdown | `060e80615cf0d739208eba646d82a9f69a5fa77a5d527414b02aa60dc58c6957` |
| `research/confirmation-60-v1/cases.json` | `545846f456d88072d3059b793f5b15f4a40aeb9cc6db87985a4028c1bfb49c1c` |

After a fresh development installation, from the checkout:

```bash
python scripts/build_60_tasks_pack.py --output-dir /tmp/h60-rebuild
python scripts/build_60_tasks_pack.py --output-dir /tmp/h60-rebuild --check
python scripts/build_60_tasks_pack.py --check
```

Paths are resolved relative to the script's checkout, so the script may also be
invoked by absolute path from another working directory. Default execution writes
the historical cases path only when absent or already byte-identical. It refuses
to overwrite different existing cases. Use a new output directory for rebuilding.
The check mode never writes and exits unsuccessfully on any byte difference.

## Interpreting hashes

The repaired builder reproduces all 60 cases **byte-for-byte**: there is no
historical case hash change to explain or replace. It checks the exact ordered
H60-01 through H60-60 inventory and required extracted sections before writing.
Its JSON report includes source/rebuilt/existing hashes, `byteIdentical`, and
`semanticEqual`. A different serialization (whitespace, key order, Unicode
escaping or line endings) can change the byte hash while `semanticEqual` remains
true. Changed task values make it false. Neither outcome authorizes rewriting
historical study inputs.

The source hash also pins Markdown line endings and descriptive prose. A changed
source fails before extraction, even if it appears editorial. Review the source
and parser diff explicitly before changing a pin. A new version of the data needs
its own directory, documented provenance/differences and study manifest; do not
silently update a historical hash to make checks pass.

This is an **offline reconstruction from a preserved study document**. It does
not recapture upstream APIs or validate that they still serve the same records.
It does not recreate the companion raw-source archive or make private evidence
public. Tasks are researcher-authored public-record adaptations with AI assistance,
not original human production prompts. No model requests or empirical results
are generated by this command.
